# Voice

The narration is generated by one of two AI engines, told apart by the voice's name, or recorded by a
person. `locutor.py` renders one `locucion/fila-NN.wav` per row, joins them into `locucion.wav` with fixed
gaps (`voice.pacing`), and writes `timings.json`: the only source of timing for the montage and the takes.

| Engine | Voice names | What it is | Pick it when |
|---|---|---|---|
| **edge-tts** | `es-MX-DaliaNeural`, `en-US-JennyNeural`… | Client for Microsoft's online TTS service; no key, needs internet. Public-output rights need separate review. | Default preview voice. Check applicable terms before public delivery. |
| **Kokoro** | `ef_dora`, `em_alex`, `em_santa` (es); `af_heart`, `am_adam`… (en); `pf_dora`, `pm_alex` (pt) | Local neural TTS (Kokoro-82M), offline, runs in its own venv. Three Spanish voices. | The voice must work offline, or English product terms inside Spanish must not sound Spanish-accented. |
| **human** | `voice.engine: human` | A person records each row. | The course bans synthetic narration. |

Both AI engines take the same `course.yaml` keys: `voice.name`, `voice.rate` (`+5%`; Kokoro reads it as a
1.05 speed multiplier), `voice.pronunciation`. `voice.pitch` is edge-tts only. Candidates in
`voice.candidates` may mix engines: `voces.py` renders them all and the user picks by ear, then one voice
for the whole course.

## Public narration: source, terms and attribution

The library license and the service/output terms are different questions. The
[edge-tts README](https://github.com/rany2/edge-tts/blob/master/README.md) describes a
client for Microsoft's online TTS service. The [package license](https://github.com/rany2/edge-tts/blob/master/LICENSE)
covers its code; it does not establish the right to publish Microsoft's generated
audio. Review the applicable Microsoft service/product terms for the chosen voice,
starting with the [Microsoft Services Agreement](https://www.microsoft.com/en-us/servicesagreement).
This review found no specific public-video permission in the cited package documents;
do not record voice-output rights as cleared based only on installation or successful synthesis.
These references were checked on November 15, 2026; no final voiceover was generated.

Before producing the final public video, record the engine/voice, applicable terms,
review date and reviewer's conclusion in the team's source inventory. The current
profile is a production template, not a license clearance. If the team cannot
establish the required rights, use a team member's English narration or a service
with appropriate documented terms. For Kokoro, review the selected model, voice
assets and dependencies rather than assuming offline synthesis settles all rights.

For generated narration, preserve the explicit disclosure in the final video/card,
upload description and MP4 metadata, and complete the submission form's AI field.
Example: `Narration: AI-generated voice (Microsoft Edge TTS).` The Errante profile
already inserts its configured disclosure into cards, description and metadata;
the form and the final hosted asset still require team review. If switching engine,
update the disclosure. If using a human voice, record it as human and remove synthetic
voice attribution by selecting `voice.engine: human`, then regenerate the cards.

## Installing Kokoro

`python kokoro_setup.py` (you run it, not the user): creates a venv under the skill's data folder
(`~/.local/share/video-tutorial/kokoro`, or `%LOCALAPPDATA%\video-tutorial\kokoro`), installs
`kokoro` + `soundfile` (torch included: a few minutes, about 1 GB) and checks for `espeak-ng`
(`brew install espeak-ng` / `apt install espeak-ng`). The first synthesis downloads the model (~330 MB).
A different interpreter goes in `voice.kokoro_python`. `locutor.py` renders every phrase of a video in one
`kokoro_synth.py` run, so the model loads once per video, not once per row.

## The course voice

- Chosen once, by ear, in the setup wizard (`voces.py`), and kept for the whole course: changing it per video
  makes the series stop sounding like one voice.
- Speed: `voice.rate` for the course; `velocidad: '+5%'` in a script's frontmatter for one video. A speed
  change moves every row: see `iteration.md`.
- edge-tts has no speaking styles; Azure Speech does (paid) if that is ever needed.

## Pronunciation dictionary

`voice.pronunciation` in `course.yaml`: respellings applied only to the text sent to the voice.

- **Keys can be phrases.** When a common word goes wrong in one sentence only, key the whole phrase
  (`"cuán creativa": "cuáan creativa"`), so every other use stays untouched.
- **Case-sensitive.** `System prompt` and `system prompt` are two entries.
- **Order matters**, top to bottom: a phrase goes before the single word it contains (`System prompt` before
  `prompt`), or the word is replaced first and the phrase never matches.
- Respellings that work well in Spanish voices: written accents to place the stress (`aidéntiti`, `doméin`,
  `óuner`, `bálanzd`), a leading `e` before `s` + consonant (`estárt`), doubled letters to lengthen
  (`cuáan`), uppercase / doubled vowel for emphasis (`NOO`). Brand names often need a single word
  (`Acmeos` for "AcmeOS").
- Process: render 4–7 variants with `variantes.py --buscar`, numbered, v1 = today's; the user picks; add the
  pick to the dictionary; regenerate. If none works, offer a wording change, or Spanish for the term.
- **Send the audio, not just the list.** After `variantes.py`, deliver every generated `fila-NN-vK.mp3` to the
  user with SendUserFile (`display: attach`), one call per term, v1 included, caption = the number → respelling
  map. Never end a turn with only a table of options and a path to the folder. Same for `--textos` and
  `--velocidades` samples.

## Truncated audio

edge-tts sometimes returns a clipped file without an error. `locutor.py` treats audio read faster than 30
characters per second as truncated, asks again up to 3 times, and stops with an error after that. A
`WARNING truncated audio` line means it caught one.

## Human narration (experimental)

`voice.engine: human`: a person records each row as `locucion/humana/fila-NN.<any audio format>`; `locutor.py`
converts, measures and joins them, so the rest of the pipeline is unchanged. Re-record a row to change it.
